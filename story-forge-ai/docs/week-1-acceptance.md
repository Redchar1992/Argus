# 第一周验收清单

## 核心验收脚本

1. 打开 Web，注册一个新用户。
2. 刷新页面，确认登录状态仍然有效。
3. 点击「新建故事」。
4. 输入：
   - 标题：`她离婚后成为财阀继承人`
   - 题材：`都市情感`
   - 目标受众：`女性`
   - 关键词：`复仇`
5. 创建后点击生成。
6. 确认页面展示 10 条方案，每条都有标题、开场钩子、简介、评分与评分维度。
7. 选择一条并保存。
8. 返回「我的作品」，刷新浏览器。
9. 再次进入该故事，确认 10 条结果与所选方案仍存在。

以上 9 步全部通过即完成第一周价值验证闭环。

## 技术验收

- [ ] Vue 3 + TypeScript 项目可构建。
- [ ] 未登录访问业务路由会跳到登录页。
- [ ] JWT 会自动附加到 API 请求。
- [ ] Spring Boot `GET /api/health` 返回 `{"status":"ok"}`。
- [ ] 密码使用 BCrypt，接口不返回密码或哈希。
- [ ] 用户只能查看、生成和修改自己的故事。
- [ ] AI 调用的请求、成功结果或错误状态会写入 `ai_task`。
- [ ] FastAPI `GET /health` 返回 `{"status":"ok"}`。
- [ ] Topic Agent 固定返回 10 条结构化选题。
- [ ] Score Agent 输出总分及冲突、反转、情绪价值、短剧适配四个维度。
- [ ] 不配置 API Key 时，完整链路仍可演示且明确显示 `local-template`。
- [ ] 三个服务测试通过，前端生产构建通过。

## 第一周不验收

正文、人物卡、大纲、编辑器、视频、社区、支付和推荐都不属于本次验收，
不得用这些功能延迟核心闭环交付。

## 价值验证建议

只记录三项：

1. 用户是否至少收藏/保存一个方案；
2. 用户认为前 10 条里“可继续创作”的方案数量；
3. 用户第二次打开同一故事时是否愿意继续。

这些数据足以决定是否进入第二周的人物、大纲和商业评分链路。
